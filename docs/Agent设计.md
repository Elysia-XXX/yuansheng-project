# 从看板到原声 Agent

## 用户与核心任务

主要面向产品、质量、客服人员。原系统要求先选看板维度再筛选，业务问题往往需要跨页面寻找样本。新入口允许用户直接提出问题，例如“京东养生壶的差评主要集中在哪里，给我几条原声”，模型通过多步工具调用取得统计和样本，再形成有依据的答复。

首版交付目标是：提出问题 → 确定数据口径 → 查询/统计/计算 → 查看证据 → 继续追问。原声导入和管理仍是业务页面，Agent 工具均只读。

## 运行结构

```text
Vue 对话工作台
  └─ POST /api/agent/chat（当前问题、最近12条历史）
      └─ Flask Agent Runner
          ├─ model：兼容 Chat Completions tools 的模型
          │    └─ tool_calls → 校验 → 执行 → tool observation → 模型
          └─ demo：显式固定规则演示，使用虚构数据
               ↓
          工具注册表
          ├─ describe_data    数据说明、字段、口径
          ├─ search_records   关键词、平台、SKU、品类、评价、日期
          ├─ aggregate_records 指定维度的完整筛选集合统计
          ├─ get_record       原声和最新标签
          └─ calculate        受限算术表达式
               ↓
          PostgreSQL / 隔离演示样本
```

工具调用协议参考 [官方 OpenAI Function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)。复用原项目的 OpenAI SDK，与既有 MiMo 配置兼容；没有引入另一个编排框架。

## 数据口径

- 查询直接在数据库筛选和聚合，避免把完整数据集加载到模型或 Python 内存。
- `dataset_info` 每条原声记一次。通过相关子查询关联最大的 `analysis_result.id`，同一原声重复分析不会放大统计。
- 查询日期使用 `complaint_time`，为空时使用 `created_at`；起止日期均包含当天。
- 支持平台、SKU、三级品类、评价等级、原文关键词及日期筛选。关键词按字面匹配，转义 SQL 通配符。
- 可按平台、三级品类及上级品类、SKU、评价等级、一级功能标签、情绪、问题性质、诉求、月份分组。
- 空标签单列“未标注”。占比的分母为筛选内全部原声，不把 Top N 分组总数当分母。
- 原声样本每次最多30条；分组最多返回100组并提示截断；统计样本总量仍是完整筛选集合。
- 详情不向模型主动暴露客户画像和订单字段。原文自身的敏感信息仍需数据治理。

## 执行与失败处理

模型上下文只接受 user/assistant 历史，服务端 system 提示由代码维护。每次工具调用由 Pydantic 严格检查参数；只开放注册工具，无任意 SQL/代码执行入口。算术通过 AST 白名单解释，限制输入长度、节点数、数值范围和指数。

每轮最多6次模型请求、总计12次工具调用。模型单次请求20秒、关闭SDK重试，总轮询起始时间预算80秒（在途请求可延后完成）。PostgreSQL 查询设置事务内单语句超时5秒。数据库异常回滚事务；工具异常作为 observation 回传，允许模型修正。模型失败、预算耗尽时保留已完成工具记录供用户核对。

返回数据包括运行ID、模式、状态、答复、工具名称、参数、结果、状态和耗时。工具调用记录随完整答复一起返回；首版没有流式事件或实时进度推送。

浏览器最多保存最近10个对话；请求携带最近12条消息，消息附带长度受限的工具记录供追问理解。本地存储失败时页面提示，本次对话仍可继续。后端无会话数据库，不承诺跨设备、跨浏览器恢复。

## 演示与真实模式

演示模式由 `AGENT_DEMO_MODE=true` 显式选择。不连接业务数据库，不请求模型；界面与答复均显示“虚构/固定规则”。它用于验收交互、工具返回结构和计算，不能用来判断模型分析质量。演示中业务管理页提供模式说明，避免展示无法使用的导入表单。

真实模式使用 PostgreSQL 及配置的模型服务。模型能力、接口兼容、认证和真实数据库连接需在部署环境单独验收；自动化测试用模型模拟器和SQLite夹具验证编排与查询逻辑。

## 后续演进

按业务规模优先补充：用户/数据集级授权；后端会话与审计持久化；流式工具事件与取消；模型任务评测集；查询缓存和复合索引。数据量增长时评估 latest-analysis 子查询执行计划。若要开放任意代码计算，应另建隔离执行环境，不能把当前算术工具直接扩展为 eval。
